# 真实分析与费用护栏

状态：WO-008 本地候选修订，2026-10-28。新增报告忠实性校验与 prompt-4；既有计费、本机／试用模式及重试上限保持不变。本单不部署，不发真实模型或 Upstash 请求。

## 配置与调用

用户本人在当前检出的交互终端运行 `npm run setup:env`。非 TTY、`.env.local` 未被 Git 忽略、配置文件为符号链接时拒绝；密钥隐藏输入，不回显字符或星号。只替换四项变量，保留其他行；覆盖前询问。Agent 不读取或操作真实配置文件。`.env.example` 仅含空变量与说明。

默认值：Base URL `https://easyrouter.io/v1`、型号 `deepseek-flash`、账本 `<用户主目录>/.jdelight/usage-ledger.json`。首次以独占创建方式建立空账本，已有账本不读取、不覆盖；损坏账本不能通过重新填写配置清零。配置改动后重启应用。四项缺任意一项、指定型号不符或账本不在仓库外时不可用。

`src/server/` 每个代码文件首行导入 `server-only`，浏览器只请求本机接口。服务端仅通过内置 fetch 向 `https://easyrouter.io/v1/chat/completions` POST。只有 `localhost` / `127.0.0.1` Host 可访问，存在 Origin 时还须同源，POST 只收 JSON。禁止重定向，超时 90 秒。请求与响应限制大小；不输出原始模型错误或返回体。

`GET /api/analysis/status` 只返回 available、used、maxCalls、costUsedCny、maxCostCny、uiRemaining；无配置时 available=false，不暴露配置值。账本损坏时 available=false，并按上限表示不可用，不能据此当作真实消费统计。`POST /api/analysis` 只收原文版本 id、text、lines；行号和分区须与全文重新计算的结果完全相同。成功只回 content；失败回 check / quota / network / config 和中文 reasons。响应头 `X-JDelight-Receipts` 只含本次调用编号、结果、token、估算费、耗时，不含原文或配置。

提示词版本 `prompt-4`，由程序写入报告 `ruleVersion`；写作规则随代码保存，以 Zod 生成 JSON Schema。原文用随机数据分隔符隔离，明示其内指令均为待分析文字。模型不生成 ID、版本和来源字段；程序补齐后跑 V1–V10，通过才返回并保存。新增 V8 条件不改写、V9 报告头不补字、V10 替代要求须确认，详见[本地数据模型](本地数据模型.md#报告生成与历史兼容)。提示词提供数字和截断反例，准备建议改为证明能力而非承诺替代经验。结构、JSON 或内容检查失败带中文原因重试一次，每次均计次。重试因额度或账本护栏被拒绝时，保留已经取得的校验原因，并附上拒绝重试的原因；不返回不合格报告。网络失败不自动重试。取消中止等待，已经预留的调用仍计次。

WO-002d 程度词：`requirement.degree` 只能填该条任一 `citations[].quote` 中出现的程度词原文（精通、熟悉、了解、熟练、掌握等），没有就填空字符串，禁止自拟概括。程序补齐字段后、V1–V7 前逐条检查，非空且在该条所有 quote 中都找不到的 degree 清空；不视为失败、不发额外请求。仅处理新模型报告，不改示例、占位和历史报告。

WO-002d 格式修复：只在本机服务端的 `JSON.parse` 失败路径调用精确依赖 `jsonrepair@3.15.0` 再解析；修复后照常补齐字段、清空无依据程度词并完整校验 V1–V7，不补章节、不免除任何规则。修复成功不增加调用次数；修复失败或修复后不合格沿用最多一次重试。模型原文、解析后与补齐后的内容仍检查密钥，命中就省略失败内容；不记录原始异常或日志。

WO-002c 提示词限长：一句话解读 ≤ 60 字；每条重点 text ≤ 60 字、basis ≤ 80 字；每个 Claim text ≤ 120 字；每段 ≤ 3 个 Claim；能力解析 ≤ 6 项；场景推测 ≤ 3 项；准备建议 ≤ 6 块；待确认事项 ≤ 5 条。整体简洁，不重复原文；原文未体现的章节直接 `not_in_source`。这些是生成指令，不新增程序长度校验；`max_tokens` 仍为 12000。

混写多个条件时每个条件单独一个 requirement，phrase 保留该条件原文，quote 只引所在片段。V4 将每条引用行按 `，,；;。！？` 切成分句，任一包含 phrase 的分句含“优先 / 加分”，或引用行在 bonus 分区，均不得写 required；phrase 未完整落在任何分句时保守按整行判断。“优先 / 加分 / 者优先”所在分句的条件在提示词中要求 preferred。V6 收紧为 phrase 须出现在至少一个 citation.quote 中。其余规则不变；已保存报告仍只校验结构，不追溯套用新规则。

请求显式使用 `thinking: { type: "disabled" }`，适配本机 90 秒的 JSON 生成流程。[DeepSeek 官方参数说明](https://api-docs.deepseek.com/guides/thinking_mode/)（2026-10-22 查阅）指出该型号默认开启高强度思考；首次冒烟超时后据此补齐模式参数，不改型号、超时、校验规则或次数 / 金额上限。首次超时的具体原因尚不能仅据此确定，EasyRouter 透传行为由后续实际调用验证。

## 记账与费用

常量：总计最多 10 次、累计估算 ¥5，先到为准；施工冒烟最多 2 次，合并后质量验证最多 8 次。自动重试占用各自额度。账本在仓库外，用户可以跨检出使用同一路径；两阶段共享总次数和总金额，不提供自动重置接口。页面开关与失败重试按钮的剩余次数使用 uiRemaining，即施工冒烟剩余与总次数剩余中的较小值；若金额不足预留下一次、配置或账本不可用，同样返回 0 且不显示开关。available 只在 uiRemaining 大于 0 时为 true。总次数与费用仍分别显示累计用量，质量验证的 8 次不会算进界面可用次数。

发请求前原子写入 pending（同目录临时文件、同步落盘、rename），成功后才发请求。结果补记 token、估算费、耗时、ok / check_failed / format_failed / network / timeout。补记失败保留 pending，停止后续请求；缺失 usage 或进程退出按本次最高估价计。账本缺失、损坏、不可读或不可写都拒绝，绝不当作零次。记录编号须唯一，账本只存时间、用途、型号和用量，不存原文、报告、请求头或凭据。

每个账本在单进程内串行；`.lock` 独占文件还防止多个进程同时写。异常退出可能留下 lock：应先确认相关进程已停止、保留账本并核对 pending 后，由用户处理锁文件；程序不自动删除旧锁或重建账本。

价格查阅日期 **2026-10-22**。EasyRouter [公开模型价格数据](https://easyrouter.io/api/pricing) 中 `deepseek-flash` 为 model_ratio=0.15、completion_ratio=4，default 分组倍率=1；[官方模型广场](https://easyrouter.io/pricing) 页面按 model_ratio × 2 × 分组倍率显示每百万输入 token 美元价，输出乘 completion_ratio。因此本候选按 **输入 $0.30 / 百万、输出 $1.20 / 百万，1 USD = 7.3 CNY** 估算，不计缓存折扣。非 default 分组或后续调价的实际账单可能不同，本地金额是估算，不是平台结算额。

上界为输入 65,536 token、输出 12,000 token；prompt 的 UTF-8 字节数加 2,048 协议余量不得超过输入上界。每次最高预留按两项上界算费，向上取整到微元。usage 非法、缺失或超出上界时不降低预留额。已用估算费 + 本次最高预留 > ¥5 时不发请求。

官方接口依据：[Chat Completions](https://docs.easyrouter.io/zh/docs/api/ai-model/chat/openai/createchatcompletion)、[模型列表](https://docs.easyrouter.io/zh/docs/api/ai-model/models/list/listmodels)、[定价说明](https://docs.easyrouter.io/zh/docs/guide/pricing)。

## 质量验证与无费用检查

合并后由总控运行：

```sh
npm run quality -- --jd D:/jdelight-local/fictional-jd.txt --out D:/jdelight-local/results
```

两个路径均须为仓库外绝对路径。输入须普通文本，禁止敏感配置文件名；先验证输出可写，再运行同一服务端代码、同一账本和全部校验。每轮新建独立输出子目录，生成 report.json（仅成功）、validation.json、usage.json。失败退出码为 1。命令加载当前检出的本机配置，不打印原始异常；输出不进入仓库。Node 24 原生 TypeScript 模式使用实验性的 transform-types 参数，避免新增依赖。

WO-002c 起，每次失败尝试单独留存：可解析 JSON 的写 `attempt-N-rejected-report.json`（结构合法时为程序补齐字段后、校验前的报告；无法补齐时保留解析后的 JSON），JSON 无法解析的写 `attempt-N-rejected-output.txt`（模型 content 原文）。重试成功也保留前次失败；未取得模型 content 时无内容可留存。服务端检查原文与解析、补齐后的 JSON 是否含密钥，命中就不返回失败内容，`validation.json.rejectedAttempts` 记录省略原因；正常留存则记录尝试序号和文件名。WO-002d 增加每遍的 `reasons`：V 编号与中文原因，无法解析则为“格式无法解析”；没有可保存内容的失败也记录原因。诊断仅经内部 `attempts` 传给质量脚本，不进入 HTTP 响应体、响应头或界面，服务端不写日志。

`usage.json.receipts` 每次尝试增加 `finishReason`，取 `choices[0].finish_reason` 的字符串值，缺失或非字符串为 null；含密钥时同样省略为 null。该字段仅在内部诊断与质量输出中出现，不写账本，不改变 HTTP 用量回执。

WO-002d 的 `usage.json.receipts` 逐遍增加 `repaired`（本地修复且重新解析成功为 true，否则 false）与 `clearedDegrees`（该遍清空条数，无则 0）；`validation.json.clearedDegrees` 汇总本轮所有尝试的清空条数，包含被拒尝试。字段仅用于观察，不写账本，不改 HTTP 契约。

`npm run check` 不需要配置，所有生成测试用假 fetch / Playwright 接口拦截。生产构建之后扫描 `.next/static`，存在 EASYROUTER、假密钥哨兵或 jsonrepair / JSONRepairError 标记则失败，确保修复库只在服务端；空目录、缺失目录也算失败。截图、axe 与日志在 `.cache/evidence/`。`npm run test:e2e -- tests/e2e/real-analysis.spec.ts` 可在构建后无费用查看开关、失败和用尽状态。真实冒烟与质量内容好坏仍需配置后分别验证，不由假接口测试替代。

## 试用模式（WO-004）

### 模式与配置

所有判断只在服务端。没有试用配置且不在 Vercel 时走原有本机模式；任一试用变量非空，或平台标记 `VERCEL=1` 时进入试用配置检查，缺项、非法或存储故障一律不可用，不回退文件账本或不计费路径。`quality` 仍只使用原本机文件账本与 10 次／¥5 常量。

| 变量                                    | 含义                                                                                    |
| --------------------------------------- | --------------------------------------------------------------------------------------- |
| `EASYROUTER_API_KEY`                    | 模型服务密钥，仅服务端，沿用原校验                                                      |
| `EASYROUTER_BASE_URL`                   | 沿用指定模型接口地址                                                                    |
| `EASYROUTER_MODEL`                      | 沿用指定型号                                                                            |
| `UPSTASH_REDIS_REST_URL`                | Redis REST 的 HTTPS 根地址，不含用户名、密码、路径、查询或片段                          |
| `UPSTASH_REDIS_REST_TOKEN`              | Redis REST 写权限令牌，仅服务端                                                         |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel Marketplace 兼容名称；与上一组二选一，不能混配；主组填写不全时拒绝，不用别名补齐 |
| `JDELIGHT_INVITE_HASHES`                | 规范化邀请码的 SHA-256 十六进制哈希，逗号分隔，不含明文码                               |
| `JDELIGHT_ALLOWED_HOSTS`                | 逗号分隔的精确 Host，无协议、路径或通配符；本机假接口预览可带端口                       |

试用不使用 `JDELIGHT_LEDGER_PATH`。服务端常量独立固定：总 `30_000_000` 微元（¥30）；每码 `15` 份；每码最多 `40` 次模型调用（含失败、取消和自动重试）。每次按原算法预留 `248_644` 微元，不提供线上重置或内存回退接口。

### 原子计费、退份与回执

`trial-store.ts` 的单段 Lua 通过 REST `EVAL` 执行，使用同一 hash tag 的四个键：全局及按码计数、分析占份记录、调用预留记录、最近回执。`claim` 原子占一份；每次模型调用的 `reserve` 在同一脚本内核对总金额与该码调用数，再同时增加预留费用、调用数及预留记录。只有确认记账后才发请求。两次自动尝试共享一次占份，各自预留、计次和结算。

费用全程为整数微元。有效 usage 的估算费替代最高预留，差额退回；usage 缺失／非法、网络失败或超时不降预留。存储超时、非 2xx、重定向、非法响应或脚本报错，停止分析；不把异常当成零费用。成功报告只有在记账及份数状态确认后才交给客户端；结算失败保守保留占用。

失败、取消、不合格报告退还这次占份，但不退调用数，费用按该次实际可确认用量或最高预留计。未完成占份有 600 秒租约（大于路由 300 秒上限），在该码后续状态查询或操作时回收被终止进程的占份；金额、调用数和成功份数不随时间重置。过期分析不能再标记成功。

调用开始先写 pending 回执，结束在列表内更新同一编号，最多保留最近 1000 条。只含编号、类型、时间、码哈希前 8 位、结果、token、估算微元和耗时；不含原文、报告、IP、请求头或凭据。完整哈希仅用于服务端计数与关联记录，不返回客户端。

REST 使用 `Authorization: Bearer`、JSON 命令数组、10 秒超时、禁止重定向，响应最多 64 KiB；无自动网络重试。生产固定命名空间 `{jdelight-trial-v1}`，没有可由请求更改的账本前缀。内存实现只用于显式测试注入。

### 邀请码、状态与访问

`npm run codes:new -- --count 20 --out <仓库外绝对路径>` 用系统密码学随机数生成 10 位码，显示为 `XXXXX-XXXXX`，去掉易混字符。只向独占新建的仓库外文件写明文，拒绝覆盖和仓库内路径；终端只输出逗号分隔的哈希。本单测试采用确定性虚构码，施工方不运行真实生成。

输入去短横线、转大写后哈希，服务端对所有已登记哈希做常量时间比较。浏览器确认有效后尝试保存规范化码；localStorage 失败不阻断本页，刷新后可能需重输。状态与分析请求均放 `X-JDelight-Invite` 头，不放 URL 或请求体。同码多设备共用服务器额度。

试用 Host 必须精确命中允许列表；POST 必须带与 Host 和协议一致的 Origin，只收 `application/json`（可带 charset）。请求 2 MiB、模型响应 1 MiB 限制沿用原实现。分析路由为 Node 运行时并导出 `maxDuration=300`。

`GET /api/analysis/status` 无码／无效码只返回 needCode／invalidCode，不访问账本；有效码返回本码 `codeRemaining = min(未占份数,剩余调用数,总余额可预留次数)`、trialEnded 及必要可用性标记。不会返回总花费、总上限、其他码、哈希或配置。分析 POST 在预留前验证码；报告、失败分类及本次调用回执头契约不变。

校对页仅在试用模式显示邀请码入口、有效码剩余份数、按码用尽或试用用尽状态；有效码且有剩余份数时默认勾选真实分析，用户可取消。无码仍可模拟，本机模式原开关保持。失败页沿用布局，试用失败不展示本机总计数与金额。

### 真实提问（WO-005）

`POST /api/answer` 只在试用模式可用，沿用允许 Host、同站 Origin、JSON、请求头邀请码校验；本机模式与无码仍使用客户端示例解答。接口是 Node 运行时，`maxDuration=60`。请求体严格为 `jobId`、`question`、`selected`、`source`；问题与选中文字各 1–2000 字。系统提示及数据 JSON 的 UTF-8 字节数加 2048 余量，超过 `QUESTION_MAX_INPUT_TOKENS=16384` 时在预留前拒绝，中文原因“原文太长，暂时无法提问”，不写入记录。

模型、地址和密钥校验沿用试用配置；JSON 模式、关闭思考、禁止重定向，输出上限 1500 token，超时 45 秒，不自动重试。随机分隔符隔离不可信原文、问题与所选文字。提示要求简体中文、约 400 字以内，依据原文和通用常识，不编造招聘方信息。输出严格为 `{answer,kind}`；答案去首尾空白后 1–1200 字，kind 只能 `common`（通常）／`inference`（推断）／`speculation`（推测），禁止 `source`。非法输出或含模型密钥、Redis 令牌内容时失败，不返回模型原文或诊断详情。

提问常量独立于分析：每码 `PER_CODE_QUESTIONS=20` 次解答、`PER_CODE_QUESTION_CALLS=30` 次调用。最高预留 `QUESTION_CALL_RESERVE=49021` 微元（¥0.049021），按 16384 输入／1500 输出与现有单价估算；实际平台价格限制沿用前文说明。

Lua 增加 `question-reserve`、`question-settle`、`question-finish`，与分析共用四键及总 `cost`，同一脚本原子检查总额、提问份数与提问调用数后一起预留。有效 usage 按实际估算费结算，未知用量、网络和超时保留最高预留；失败、取消或输出校验失败退一次提问，已确认费用与调用数不退。结束或 600 秒租约过期后删除占用记录，仅保留 pending；成功计数仍保留，重复结束返回 `state`，不重复退次。缺失类型的旧分析记录按 analysis 解释；不重置既有分析计数或金额。回执增加 `type: analysis|question`，只存类型和原有用量字段，不存问题、所选文字、原文或解答。

状态增加 `questionsRemaining=min(20−已用提问,30−提问调用数,总余额可预留次数)` 与 `questionCallLimitReached`。分析额度耗尽不妨碍仍有余额的提问；仍不返回总额、费用或配置。成功响应 `{ok:true,answer,kind,questionsRemaining}`；失败 `{ok:false,kind,reasons}`，kind 为 check／quota／network／config。最终记账未确认时不给解答。

问题仍先保存在本机，失败可重试，每次重新发出的模型请求独立计次。解答按返回 kind 保存；加入报告不调用模型。若解答已返回但本机保存失败，本页面内重试只保存缓存的解答，不重复提问。关闭面板取消正在等待的请求。

### 试用提示与反馈（WO-005）

持久存储申请在应用加载后执行一次，已持久则跳过，结果静默。首页按新生成的基础报告计数（补充产生的新版本不重复计数）：成功导出后新增 3 份，或有报告且距离上次导出／第一份报告满 7 天时提醒。导出记录包含快照中的基础报告编号，下载期间同一毫秒新增的报告仍算未备份。导出失败不清零；关闭备份或微信提示仅本会话有效。iOS Safari（排除其他 iOS 浏览器及微信）且不在主屏幕模式时提示添加到主屏幕，关闭后 30 天内不再显示。微信提示适用于全部页面；同屏最多两条，备份优先于 iPhone。客户端存储读写均捕获异常，失败隐藏提示且不报错。

### 自检与验证边界

`npm run trial:selfcheck` 读取调用进程的 Redis 环境变量，不自动读取配置文件、不读取邀请码明文。它只在随机 `{jdelight-trial-selfcheck-<uuid>}` 前缀验证分析与提问的预留、结算、退次、20／30 次提问限制及各 25 个混合并发不超总额，结束删除该前缀四键；删除函数拒绝生产前缀。没有模型调用。WO-004／WO-005 只以假存储测试；真实 Redis 的 Lua 执行和此脚本留给总控在 WO-006 授权后验证。

客户端扫描同时拒绝两组 Redis 变量名、邀请码哈希配置名、哈希测试值及模型专用标记；测试验证每种标记都能被检出。Lua 全文有单独快照；内存语义、假 REST、费用／份数／并发／故障／访问和两种宽度 A–D 状态均有自动测试。
