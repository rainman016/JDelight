# 本地数据模型 · 结构版本 1

状态：WO-002 实施候选，2026-10-21。依据 R006 已确认的第一批工单方案、报告数据结构 v1 与 WO-002 本地数据契约草案；合并前待规划方独立复核。

数据只存在当前浏览器 IndexedDB，数据库名 `jdelight`，通过 Dexie 4.4.6 读写。没有账号、服务端存储、模型调用、网络数据发送。领域契约见 [schema.ts](../../src/domain/schema.ts) 和 [report.ts](../../src/domain/report.ts)。

## 表与索引

| 表             | 主键 / 索引                      | 字段与约束                                                                                                                                                                                                                                                                                                                                                                   |
| -------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jobs           | `id`；`updatedAt`、`mark`        | title、company、place，取不到存空字符串，页面显示“未显示”（空岗位名显示“未命名岗位”）；mark 为 preparing / interviewed / dropped；note 按 Unicode 码点最多 60 字；status 为 saved / analyzing / failed / ready；currentSourceVersionId；currentReportVersionId 可空；lastError 可空，含 kind（check / quota / network / save）与 reasons；createdAt、updatedAt、lastViewedAt |
| sourceVersions | `id`；`jobId`                    | id、jobId、no、text、lines、confirmedAt；原文完整保留空格、空行与换行符；展示行号从 1 开始；lines 通过程序识别 meta / duty / must / bonus / other，含 heading、itemNo；空行占号，条目序号按各分区非标题、非空行累计                                                                                                                                                          |
| reportVersions | `id`；`jobId`、唯一 `[jobId+no]` | id、jobId、sourceVersionId、no、parentId、content、change、createdAt。WO-002 只写 no=1、parentId=null、change.kind=base；content 通过 V1–V7 后才写入。每版完整快照                                                                                                                                                                                                           |
| supplements    | `id`；`jobId`                    | 预留，不经产品路径写入；question、answer、answerKind（source / inference / speculation / common）、anchor、status（unanswered / answered / added / withdrawn）、addedInVersion（可空）、createdAt、updatedAt。anchor 含 blockId、start、end、exact、prefix、suffix、reportVersionId、sourceVersionId、offsetUnit=utf16                                                       |
| meta           | `key`                            | value；首次建库写 schemaCreatedAt（ISO 时间）                                                                                                                                                                                                                                                                                                                                |

ID 使用 `crypto.randomUUID()`，时间统一 ISO 字符串。未来结构变更必须新增 `version(n)` 并保留旧定义，使用 `upgrade()` 回填，不清库升级。

## 仓储与事务

页面只通过 `src/data/repository.ts` 访问数据。domain 不依赖 Dexie 或 Next。所有写入操作均在 `rw` 事务执行；事务中不等待网络、动画或其他无关异步。

| 操作                   | 原子写入                                                                                        | 失败处理                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 确认原文并新建岗位     | jobs(saved) + sourceVersions(1)                                                                 | 两者同时回滚；校对页保留输入。请求 ID 在首次点击分配，重复点击、同一请求重试只返回同一岗位；原文或元信息不符则拒绝                                           |
| 开始 / 取消分析        | 更新 jobs 的 status、lastError、updatedAt                                                       | 开始失败时原文仍在；取消将未提交分析恢复为 saved。事务已开始保存报告时等原子完成，不能把 ready 回写成 saved                                                  |
| 保存报告               | 事务外 V1–V7；事务内检查岗位、当前原文及预期父版本，新增 reportVersions，再更新岗位指针与 ready | 任一步失败整笔回滚；新版本不存在，指针及状态不变。父版本冲突不覆盖；迟到的开始、取消或失败状态不降级另一页面已提交的 ready 结果。WO-002 拒绝第二次 base 创建 |
| 分析失败               | jobs.failed + lastError                                                                         | 原文保留；若连失败状态都写不进，页面显示原因，首页仍有原文卡                                                                                                 |
| 改标记、备注、记录查看 | 只更新 jobs 对应字段与 updatedAt                                                                | UI 只在成功后更新，失败给中文提示；备注草稿保留可重试                                                                                                        |
| 删除                   | 同事务删除 sourceVersions、reportVersions、supplements 中该 jobId 的所有记录，再删除 jobs       | 任一删除失败全部回滚，提示“删除失败，数据没有变化”                                                                                                           |

原文与报告表均有 Dexie `updating` hook 拒绝修改，`update()`、对现有键的 `put()` 同样拒绝；仓储不提供版本更新函数。删除只通过跨表事务执行。浏览器存储可被用户自行修改，此约束不声称能防止用户通过开发者工具篡改。

## 报告检查与展示

V1 严格结构、版本关联、7 章顺序、块类型与稳定 ID 唯一；V2 引用行与逐字连续片段；V3 原文 / 推断及速览项必须有出处；V4 优先、加分不升级为必备；V5 gist 必须为推断、probe 必须为推测；V6 要求措辞须在所引原文行；V7 每层严格对象拒绝任何额外字段（含分数）。不通过不保存、不展示，返回中文原因。

示例 JD 返回 `fixtures/sample-report.json` 的完整七章报告；首尾空行或 CRLF 不改原文，引用行号按真实行重新定位。其他 JD 返回明确标注的占位内容，不借用示例岗位的判断。

来源草案第 7 节“占位句全部 common、无引用”与 gist / focus 的 V3、V5 约束有字面冲突。本候选优先满足 V1–V7：章节占位 Claim 为 common、无引用；gist / focus 保留契约规定的类型及输入上下文引用，并明确写“示例分析：真实内容由分析生成”，basis 说明未对岗位作判断。该取舍待独立复核，不扩展真实分析。

## 取消与恢复

确认前不创建岗位、不分析。确认后立即原子保存原文；取消解析回到校对页，但已确认原文与元信息只读，给“继续分析 / 返回我的岗位”，避免以取消为由改写不可变原文。刷新或离开页面时若分析未完成，首页显示待分析卡，可使用保存的原文重试。单页用同步互斥防止重复确认 / 重试；跨连接由保存时的父版本比较与唯一索引防止覆盖和重复版本。
