# 本地数据模型 · 结构版本 2

状态：WO-003 本地候选（2026-10-23），阶段 A 已获规划方“继续”，B、C 待评审与高风险独立复核。依据已确认的施工指令；保留 WO-002 / WO-002b / WO-002c 的报告规则与费用边界。

数据只存在当前浏览器 IndexedDB，库名 `jdelight`，使用 Dexie 4.4.6。页面通过 `src/data/repository.ts` 访问数据；domain 不依赖 Dexie、React 或 Next。原文和报告版本不可改写；问题、补充状态与岗位元信息可以更新。报告结构、来源和规则版本见 [schema.ts](../../src/domain/schema.ts)、[report.ts](../../src/domain/report.ts)。

## 表与索引

| 表             | 主键 / 索引                      | 内容与约束                                                                                                                                                                                                                                                                       |
| -------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jobs           | `id`；`updatedAt`、`mark`        | title / company / place，空值显示“未显示”（空岗位名为“未命名岗位”）；mark 为 preparing / interviewed / dropped；备注按 Unicode 码点最多 60 字；status 为 saved / analyzing / failed / ready；currentSourceVersionId、currentReportVersionId、lastError、创建／更新／最近查看时间 |
| sourceVersions | `id`；`jobId`                    | no、完整原文、逐行分区与条目编号、confirmedAt；保留空格、空行与原始换行；不可变                                                                                                                                                                                                  |
| reportVersions | `id`；`jobId`、唯一 `[jobId+no]` | sourceVersionId、no、parentId、content、supplements 完整快照、change、createdAt；第 1 版 base 永久保留，加入／修改／撤下各创建新版本                                                                                                                                             |
| supplements    | `id`；`jobId`                    | question、answer、answerKind、anchor、status（unanswered / answered / added / withdrawn）、addedInVersion（可空）、createdAt、updatedAt；提交问题即保存，解答失败不删问题                                                                                                        |
| meta           | `key`                            | schemaCreatedAt；dataRevision、exportedRevision；lastExportAt。只在本机使用，不进入备份文件                                                                                                                                                                                      |

ID 使用 `crypto.randomUUID()`，时间使用 ISO 字符串。`ReportVersion.supplements` 每项为 `{ supplementId, question, answer, answerKind, anchor, addedInVersion }`，是该版本当时的完整副本，旧版本不从当前补充表重建。

## v1 → v2 升级与不可变保护

保留 `version(1)` 的原始五表定义，追加 `version(2).stores({}).upgrade(...)`。升级只在 IndexedDB 的原子 versionchange 事务内用原生游标为旧报告回填 `supplements: []`，保留全部记录、原文、报告正文与建库时间；失败整体回滚，不清库。运行期的原文、报告 `updating` hook 始终开启，`update()` 与覆写 `put()` 仍拒绝。

删除岗位只通过一个跨表事务删除对应的原文、全部报告版本、问题与补充和岗位记录；任一删除失败全部回滚。此约束不声称防止用户用开发者工具修改其浏览器存储。

## 报告生成与历史兼容

新基础报告保存前运行 V1–V7：严格结构与七章顺序／块类型／稳定 ID 唯一；逐字引用；必要出处；要求程度不升级；gist 为推断、probe 为推测；要求措辞在至少一个所引原句中；拒绝多余字段及分数。V4 按包含 phrase 的分句判断优先／加分，bonus 分区及跨分句回退仍受约束；V6 检查 citation.quote。新模型报告 ruleVersion 为 prompt-2，模拟仍为 rules-1。

保存基础报告时，在事务内核对岗位、预期父版本、原文 ID、原文内容与逐行数据，新增报告后再切换指针。失败整笔回滚；迟到的开始／取消／失败不得把另一页面已经提交的 ready 降级。重复确认同一新建请求不会多建岗位，元信息或原文变化则拒绝覆写。

读历史报告只做存储结构校验，不重新运行现行 V4／V6 等语义检查，也不改写旧报告。示例 JD 返回预置七章报告，其他 JD 明确显示示例占位，不借用示例岗位判断。来源标识区分 mock / model。

## 提问、锚点与补充版本事务

锚点为 WO-001b 的 `blockId / start / end / exact / prefix / suffix`，再加 `reportVersionId / sourceVersionId / offsetUnit: "utf16"`。start/end 为 UTF-16 半开区间、向外对齐完整字素；exact 非空且长度等于 end-start；前后文各最多 32 个 Unicode 码点。用原有 createAnchor / resolveAnchor 处理同块重复句、跨行和反向选区，不凭距离猜测失去的选区。

选中文字的锚点挂在真实文字块上。对整节提问时，以该节第一个文字块为定位点，问题注明该节；补充显示在该块下方，并显示“你选中的”原句。原文与基础判断不变。

选区、整节摘录、偏移与恢复统一使用 `getAnchorText` 的正文投影：排除 `data-anchor-ignore` 标记的类型标签、出处及其他界面说明，不折叠正文空白，也不按字面删除“通常”等正文原词。界面标记文字不可选；即使 DOM Range 跨过这些元素，exact／prefix／suffix／start／end 也只按正文计算。WO-003 尚未合并、没有用户数据，按返修指令不迁移旧锚点。

1. 提交问题：核对当前报告与锚点所属版本，在一个事务中保存 unanswered 问题、更新时间和数据修订号；同请求 ID 重试不重复创建。未提交的输入发生保存失败时仍保留在卡片里。
2. 获取示例解答：本批只调用本地可注入函数，answerKind 为 common，明确标“示例解答”。保存为 answered；失败保留 unanswered，可先记下或重试。已加入／撤下的记录不会被迟到的旧解答降级。
3. 加入／修改／撤下：事务外先计算新报告完整快照，事务内重新核对当前父版本、原文和补充是否变化，再新增报告、更新补充状态、更新岗位指针和 dataRevision。任何失败全部回滚，上一版本和解答仍在；旧页面不能覆盖另一页面的新版本。
4. 加入保存 addedInVersion 为新版本号；修改保留最初加入版本号、在新快照中替换解答；撤下移除新版本快照中的补充，当前记录为 withdrawn，旧快照不变。版本号递增，change 记录 add / edit / withdraw、补充 ID 和摘要。

readJob 在同一只读事务中返回当前报告、全部版本、关联原文与当前问题记录。旧版本只读，显示当时的补充；完整报告与导出使用所选版本，速览由该版本的 focus、toConfirm 和相应疑问组合，不另存分析数据。当前疑问草稿不会混入旧版或报告导出。

## 备份格式与导出

```text
{ format: "jdelight-backup", formatVersion: 1, schemaVersion: 2, exportedAt,
  jobs, sourceVersions, reportVersions, supplements }
```

导出全部数据先在一致的只读事务中取得四表完整快照及 dataRevision，再生成 JSON Blob、触发本地下载。下载发起成功后，才在 meta 写 lastExportAt 和该快照的 exportedRevision；下载期间又有写入时，当前修订号不同，仍显示有新改动。文件不含 meta、账本、密钥或服务端配置，没有加密。

所有用户数据写入、补充与版本变更、分析状态变化、删除、导入都在自身事务里更新 dataRevision，失败同时回滚。只查看岗位沿用原有查看时间／排序行为，不更新 dataRevision。提醒比较修订号而非时间，避免同毫秒写入、删除或多页面导致误判：

- 从未导出且有岗位：还没有备份过。
- 当前 dataRevision 等于 exportedRevision：没有新改动，不提醒。
- 导出后有新增／修改／删除／导入：提示上次备份后有新改动；即使最后一个岗位被删除也保留提醒。

报告导出与数据备份分开：复制纯文本／打印包含版本、日期、来源、类型、出处、边界和所选版本已加入的补充；不带标记、备注、未加入草稿与内部诊断，不能用来恢复数据库。

## 导入校验、预览与覆盖

本地文件限 `.json`、50 MiB。JSON 语法错误、格式不支持或比本机新，均说明原因，不写入。Zod 严格校验四表完整结构，拒绝未知字段；继续检查编号唯一、原文逐行一致、七章状态与块类型、报告版本链、当前指针、问题锚点、补充快照与状态的关联。不会调用模型或按新 V4／V6 改写旧内容。

预览展示岗位／版本／补充数、导出时间、重复岗位数，记下当时 dataRevision。确认导入前和写入事务内都再核对修订号；预览后有新写入则拒绝覆盖，要求重新选择文件查看。

- **合并**：同 ID 岗位保留两份，导入的那份加“（导入的副本）”，其原文、各版报告和问题一起换新 ID。同步更新岗位指针、jobId、sourceVersionId、content.sourceVersionId、parentId、change.supplementId、快照补充 ID 与锚点中的版本 ID。块 ID 与版本号保留。岗位 ID 不同但子记录 ID 碰撞时，也给该导入岗位的子记录换新 ID，不能覆写本机记录。没有碰撞的记录原样加入。
- **替换**：预览选择替换后，再展示清除提示与“先导出现有数据”，用户第二次确认才执行。一个 rw 事务内清空四张业务表、写入四表、更新 dataRevision；任一步失败恢复全部表和 meta。本机 meta 保留，导入不冒充一次本机导出。
